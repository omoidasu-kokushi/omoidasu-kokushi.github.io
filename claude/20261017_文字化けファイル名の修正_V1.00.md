## 2. 目次を作る.py について

- **python3 は呼んでいない**。`python3` という字は、先頭の shebang・docstring・生成する見出しの文字列の中だけにある。subprocess・os.system も無い
- ただし Windows で走らせると、`io.open(..., "w")` がテキストモードなので **CRLF で書き出し、2本とも全行が差分に出た**（333行／100行）。
  リポジトリは LF で `core.autocrlf=false`。`newline="\n"` を足して LF に固定した。Linux では元から LF なので変わらない
- 生成される見出しの「`python3 tools/目次を作る.py` が自動生成」はそのまま（Linux での書き方として正しいので触っていない）

### batchAZ が落ちた原因（推定・まだ直していない）

L106 の `async` evaluate が `const a = atoms[0]; … a.atom_id` を読む。その前の待ちは
`__APP_READY` のあと**固定 1200ms** で、`__INIT_DONE`（同梱2本の取り込み完了）を待っていない。
機械が重いとき取り込みが終わっておらず `atoms[0]` が undefined → evaluate の中で TypeError、という形と整合する。
引き継ぎ V1.53 §5-9「固定待ちの掃除（`__INIT_DONE` を待たないテストが108本）」の1本そのもの。
§5-9 の方針どおり「**赤が出たものから `__INIT_DONE` 待ちへ寄せる**」の候補。
今回は名前の修正と混ぜないため、直していない。run_all は1回目の出力が最後の1行しか残らないので、例外の本文は取れていない。
