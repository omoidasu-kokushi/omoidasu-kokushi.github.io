## 8. 作業環境の注意

- フォルダ `国家試験対策室` は device_request_folder_access で接続できる（list／stage／commit_files）。device_bash は使っていない。
  **経路の漢字は正確に**（「仕様」＝ U+4ED5 U+69D8。似た字で 404 を踏んだ）
- コンテナから GitHub は clone は通る・push は 403。反映は §6
- device_commit_files は消せない。消すのはあなたの手
- bash は1回120秒まで。長いもの（run_all 約25分・通し受験）は `nohup … &` で背景に回してログを見る。**run_all は単独で。途中でソースを直したら最初から**
- Playwright：`APP_URL=http://127.0.0.1:8900/index.html`、`window.__APP_READY === true` を待つ。
  **数を見るテストは `window.__INIT_DONE === true` を待つ**（同梱2本の取り込みと印づけが終わった合図。READY の約1〜2秒後）
- **`wait_for_function` に async の述語を渡さない**（値が 0 でも通ることがあった）。IndexedDB の数は Python 側で `evaluate` をループして待つ
- **購入済みをテストで作るなら本物の鍵で `activate()`**（`test_batchAH` の GOOD）。export の `isPaid` を差し替えても `gate()` には効かない
- **「触った問題」は台帳（ログ）から導く**（`computeWeaknessFromLogs`）。肢の `answer_count` を書いただけでは触ったことにならない
- 同梱の総数は339（本体249＋模試待ち90）。本体だけを数えるときは pool main で絞る。模試待ちの肢には評価が付かない（ノック・分析の標本にしない）
- コンテナの bash で `pkill -f "http.server 8900"` を打つと**自分のシェルごと落ちる**（コマンド文字列に一致する）。サーバは run_all が自分で立てて自分で止める。手で止めるなら `fuser -k 8900/tcp`
- 導出できるものはAIに書かせない／数が増えたときこそ増えた理由を数える／規則を2か所に持つときは片方だけ直さない
