### V2.97（ローカル・未反映）：同梱シードの取り込みが途中で止まる不具合

- **何が起きていたか**：取り込みは `__APP_READY` のあとも走る（200件ずつ）。その約1秒の間に閉じる・再読込すると
  200問だけ入って `seed_imported` が立たない。V2.96 までの `init()` は「問題数0のときだけ入れる」だったので、
  次の起動は onlyExisting 更新（既存200問の上書き）しか走らず、**残り49問が二度と入らない**。
  実測：countQuestions 200／last_import_report updated 200・skipped_missing 49／seed_version だけ 3.03
- **直し方**：`part2 init()` の条件を「問題数0」→「印（`seed_imported`）が無い」へ。印は取り込みが終わってから立てる（順序不変）。
  印あり・0問（全初期化のあと・V1.81）は入れない。続きを入れる起動では `autoMarkSplittable` を走らせない（同時書き込みを避ける）
- **テスト**：`tests/test_seed_resume.py`（19項目）。「200問・印なし → 次の起動で 249問・印あり（新規49／更新200）」
  「印あり・0問 → 再読込しても戻らない」「続きの起動では auto_split_done を立てず、その次で立つ」
- **版**：CACHE_NAME v2.97.0／?v=2.97／build-stamp 20260911_Omoidasu_V2.97。`test_seed_hisshu` の固定値を 2.97 へ

## 8. 作業環境の注意

- フォルダ `国家試験対策室` は device_request_folder_access で接続できる（list／stage／commit_files）。device_bash は使っていない
- コンテナから GitHub は clone は通る・push は 403。反映は §6
- device_commit_files は消せない。消すのはあなたの手
- bash は1回120秒まで。長いもの（run_all 約22分・通し受験）は `nohup … &` で背景に回してログを見る
- Playwright：`APP_URL=http://127.0.0.1:8900/index.html`、`window.__APP_READY === true` を待つ
- **`wait_for_function` に async の述語を渡さない**（値が 0 でも通ることがあった）。IndexedDB の数は Python 側で `evaluate` をループして待つ
- 同梱シードは READY のあと約1秒で249問。数を見るテストは249問を待ってから reload（V2.97 で止まらなくなったが、数は待つ）
- run_all は単独で。**途中でソースを直したら最初から**
- 導出できるものはAIに書かせない／数が増えたときこそ増えた理由を数える／規則を2か所に持つときは片方だけ直さない
