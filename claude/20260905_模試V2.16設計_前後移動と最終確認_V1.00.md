# 模試V2.16 設計メモ：前後移動＋提出前の最終確認（実装前・裁定済み要望）

## 利用者要望（2026-09-05）
- 本番に即して前後の問題へ行き来できる
- 全解答の提出前に、一覧スクロールで最終確認（チェック付き肢の見直し・五分五分の考え直し）
- 採点までは正誤情報を一切出さない（V2.15の思想と一貫）

## 現行の配線（読解済み）
- finishLaunch（part2）で st.exam を作り、M.hooks.afterGrade が
  「確定のたびに answers.push → stepForward → 解説フェーズなし」
- onFinish で gradeExam(answers)。onAbort=abortExam（§22-2：hooksは自分で外す）
- 選択・根拠チェックは part1 の cur（現在問題の一時状態）にしかない

## 設計（answers を配列pushからq_idキーの置き換え式へ）
1. st.exam.answers → Map的に q_id で引けるようにする（配列のままでも findIndex で置換）
2. afterGrade：既存エントリがあれば**置き換え**（再解答）。無ければ追加。
   think_ms は初回のみ記録（再解答での上書きはしない＝計測の意味を守る）
3. 「確定」後も自動前進は維持。ただし模試中はサムゾーンに「◀前へ｜次へ▶」を常設
   - 移動先が解答済みなら、answers から picked / ground_on を cur へ復元して描画
   - part1 renderQuestion に exam専用の復元フック（M.hooks.restoreExamAnswer(q_id)→保存済み選択）を1つ足す
4. 最終問題の「次へ」→ 確認画面（新モーダルではなく quiz 画面内の切替 #exam-confirm）
   - 全問リスト：問番号／自分の答え（丸数字）／根拠チェック数／未回答は赤「未」
   - 行タップでその問題へジャンプ（=移動と同じ経路）
   - 画面下に「全解答を提出する」→ ここで初めて onFinish（gradeExam）
5. 未回答が残ったまま提出 → 確認ダイアログ（「未回答N問があります。提出しますか」）
6. §22-2の遵守：onAbort は従来どおり。確認画面からのホーム離脱も abortExam を通す

## 守ること（実装時の不変条件）
- 採点・記録の書き込みタイミングは「提出」以降に一切変えない（現行も一括なので互換）
- 正誤・正解番号は提出まで画面に出さない
- think_ms の初回性
- テスト：batchCM 新設（移動で選択が復元される／再解答で置き換わる／未回答提出ガード／
  確認画面から戻れる／提出後に従来どおり採点結果）
