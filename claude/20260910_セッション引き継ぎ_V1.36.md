## 3. 【判断待ち】体験用の模試（無料版）をどうするか

利用者に聞くこと。前セッションの最後に提示して、返事をもらう前に環境が落ちた。

### いまの状態

```
返ってきた 85/90問（29本）

  M0028  未処理
実質NG 0。確認16件（数値の裏づけ5・タグ候補外4・sub_item候補外1 ほか）
```

### 問題：肢が長すぎる

| | 肢の字数 中央値 |
|---|---|
| 本試験（配布1,197問） | **9字** |
| free_a（プチ模試用30問） | 20字 |
| free_b（ハーフ模試用60問） | **26字**（21字超が72%） |

**原因は私**：バッチのヘッダーに「肢は20字以内」を書き忘れた。指示していないのでAIは長く書いた。
副作用：一問一答に回るのが free_a 22%・free_b 12%（狙いは半分以上）。

### 選択肢（私の推奨は A）

**A. 作り直す**
　`体験用の予想問題バッチを作る_V1.00.py` の `HEAD` に2行足して30本を再生成、PADで回し直す（30〜60分）。
　いまの85問は `_to_delete` へ退避。
```
(6) 選択肢の本文は 20字以内にする（一問一答へ切り出す条件が「全肢20字以下」）
(7) 全体解説は 200〜400字（仕様§4-4。過去問レーンの実測は中央値311字）
```
　メリット：本試験に近い形になる／一問一答率が7割前後に上がる
　デメリット：PADをもう30本
　リスク：低い（過去問レーンでは指示どおり作られている）

**B. このまま使う**
　M0028 を流し、M0001 を流し直す（1本目は必ず捨て駒になるので、M0028→M0001 の順か、M0001を2回）。
　その後 `体験用の予想問題を検証して組み立てる_V1.00.py` で取り込み用JSONを作る。
　模試としては使える。一問一答は必修249問（192問）でまかなう。

**どちらでも、そのあとは**：アプリでプチ模試・ハーフ模試を通す → 無料版の制限を実装（§5）。

## 8. 作業環境の注意

- bash は1回120秒まで。テスト全実行は `/tmp/run_chunk.py`（DEADLINE 95秒・`NEXT=<idx>` で続ける）を**作り直して**使う（コンテナが変わると消える）
- `python3 -u` でないと途中で切れたとき出力が消える
- Playwright の起動口：`APP_URL=http://127.0.0.1:8900/index.html`、`window.__APP_READY === true` を待つ
- 一問一答を出すには「本日の復習」で期日の肢が1〜2個の状態が要る（`tests/test_oneq_verdict.py` の `prepare()` が手本）
- **導出できるものはAIに書かせない**（確度Cの注記／一問一答の可否／模試の割り当て）。3回作り直しても毎回落ちるものは待っても終わらない
- **数が増えたときこそ、増えた理由を数える**（二重配布は「増えて見えた」）
- **重なりを疑ったら箱ではなく文字の実インクを測る**（Range.getBoundingClientRect）
- 規則を2か所に持つとき（掃除の judge_splittable と storage.js の judgeSplittable）は**片方だけ直さない**
